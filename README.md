# 码得 · made

简体中文 · [English](README.en.md)

码得（made）是本项目的设备产品名，不限定屏幕形状。当前实现基于微雪 **ESP32-S3-Touch-LCD-1.85B**，使用 **360×360 圆形触摸屏**，在 Brookesia 桌面中提供独立的 **码得** 应用。

码得自己录音，经电脑桥接客户端识别语音，然后交给 Codex、Cursor、Qoder 或腾讯 WorkBuddy。**一个任务就是一个持续对话的会话**，须在码得或电脑任务页点 `+` 显式新建；第一句话会自动成为简短标题，之后说的话都在这个任务里继续，共享助手上下文。每个助手各占一屏，左右滑动切换。单击 BOOT 开始录音，说完后静音自动上传；双击确认当前说的话，三击取消，长按退出应用。小智作为另一款桌面应用保留，不参与码得的语音链路。

### 开机与解锁

桌面只保留 **小智、码得、Settings（设置）**。开机自动进入码得锁屏；再次打开或恢复码得也先显示锁屏。绿色小豆在屏幕中跳舞，中英文文案交替显示，分别为「码得，代码触手可得」和「Made,when you want to make」。**向上滑动解锁**后进入原有助手、任务与设置界面。锁屏不连接桥接器、不上报心跳，单击、双击、三击 BOOT 均不触发录音或任务操作；锁屏和解锁后都可长按 BOOT 约 1.2 秒返回桌面。

本轮精简桌面、自动启动和锁屏交互仍待实板验收。

## 中英文界面

桥接器顶部可切换 **简体中文 / English**。偏好保存在电脑端，三个页面共用。码得的设置首页提供「连接」「语音」两个独立入口，进入「语音」后可选「中文 / English / 跟随电脑」：未连接时也可选择并保存；手动选定的语言不会被电脑覆盖，只有「跟随电脑」才在配置刷新时同步。英文界面使用产品名 **made**。旧固件需要更新一次以获得中英资源，以后切换已有语言不需重新刷写。

任务标题、指令、助手回复、代码、项目名称和插件自定义内容保留原文。界面语言不限定录音所用语言；语音客户端不再附加中文限定，具体识别能力取决于所选服务与模型。小智与桌面 Settings 的语言独立。本项目的英文入门说明见 [README.en.md](README.en.md)，扩展方式见 [国际化开发说明](docs/I18N.md)。

## 插件扩展（开源接口 v1）

编程助手通过电脑侧插件扩展，码得助手名单、名称、能力与图标像素全部由桥接器下发。未连接时只显示连接与配对状态，没有默认助手占位；固件也不内置动物绘图模板。自定义图片可用 `bridge/tools/convert-agent-icon.py` 转成 48×48、最多 16 色的小图放在插件中。语音识别不做插件化，只填 URL、API Key、模型名，兼容服务和模型共用内置转写客户端。开发说明和示例见 [插件开发指南](docs/PLUGINS.md)。安装插件或更换图片并重启桥接器后，码得自动刷新，不需反复刷固件。首次迁移到动态图像协议需要更新本版本固件。板侧事件与命令见下一章。

## 板侧事件与命令

码得上报事件，和桥接器向码得下发命令，是两条独立的设备接口。事件那次请求只表示「发生了」，响应是 `{accepted:true}`，不夹带命令。命令放在该设备自己的队列里：管控插件可以在处理事件时入队，也可以等处理函数返回后再入队；桥接器也可以不经过任何事件，直接入队。码得解锁并连上桥接器之后自行领取并执行，然后确认。USB 直连、局域网、接收器和公网都走同一套设备接口。

锁屏期间码得不连接桥接器，不上报事件，也不领取命令。队列里的命令会留到解锁之后。配网、配对和语言不在命令里。

### 事件

板上目前公开这些事件。只有已安装且启用的管控插件登记了某个事件，码得才会上报它。未登记的按键仍保持原来的录音、确认、取消和回桌面行为。

| 事件 | 何时发生 |
| --- | --- |
| `boot.click` | 解锁后单击 BOOT（同时开始录音） |
| `boot.double` | 解锁后双击 BOOT（同时确认当前任务） |
| `boot.triple` | 解锁后三击 BOOT（同时取消当前任务） |
| `boot.long` | 解锁后长按 BOOT（同时退出应用） |

设置页或删除确认框打开时，这些按键不会上报。码得 `POST /device/events`，正文为 `{"name":"boot.click"}`。字段若有，每个值最长约 120 字节。

### 命令

码得 `GET /device/commands` 领取，执行后 `POST /device/commands/ack`，正文为 `{"ids":["1"]}`。未确认的命令留在队列里，下次领取还会带上。队列最多 8 条。

| 命令 | 字段 | 板子做什么 |
| --- | --- | --- |
| `caption.show` | `text` | 显示一行提示 |
| `audio.play` | 无；附带 WAV | 播放随命令下发的语音 |
| `theme.apply` | `name` | 切换主题；`default` 恢复内置主题，成功后重启 |
| `volume.set` | `level` | 把音量设为 0–100 |
| `agent.select` | `id`，或 `direction` 为 `next` / `prev` | 切换助手 |
| `session.create` | 无 | 为当前助手新建任务 |
| `session.select` | `id`，或 `direction` 为 `next` / `prev` | 切换任务 |
| `session.delete` | `id` | 删除当前助手下的这个任务 |
| `voice.start` | 无 | 开始录音并上传 |
| `task.confirm` | 可选 `id` | 确认当前屏幕上的任务 |
| `task.cancel` | 可选 `id` | 取消当前屏幕上的任务 |

`task.confirm` 和 `task.cancel` 不写 `id` 时，作用于当前可见任务。主题名是桥接器 `themes/` 里的目录名。

播放语音时，语音和命令一起入队。码得看到 `audio:true` 后，再 `GET /device/commands/<id>/audio` 取走同一段 WAV 并播放。格式为 16-bit PCM WAV，采样率 8k–48k，单声道或双声道，不超过 256KB。队列里同时只保留一条待播放语音。

插件调用 `send({name,fields})`；播放语音时第二个参数是 WAV。插件只能下发自己 `commands` 里声明、并且板侧清单里已有的命令。示例见 `bridge/examples/plugins/board-caption.mjs`。

桥接器直接下发走本机工作台，须带本机操作令牌：

```sh
curl -X POST http://127.0.0.1:8787/api/board/commands \
  -H "content-type: application/json" \
  -H "x-vibe-token: <本机操作令牌>" \
  -d '{"deviceId":"<12位设备号>","name":"caption.show","fields":{"text":"你好"}}'
```

语音用同一个地址，`Content-Type` 为 `audio/wav`，查询参数 `deviceId` 指出哪块板，正文就是 WAV。这条路径只要求命令在板侧已上报的清单里。旧固件的清单只有 `caption.show`；要使用上表中的其余命令，需要烧录包含该清单的码得固件。

## 仓库模块

五个功能模块用英文目录名。市场只做包管理，与码得和桥接器解耦；包安装进桥接器之后才生效。技能广场不在本仓库自建。

- `made/`：**码得固件**。从微雪 1.85B 官方 Brookesia 示例出发，保留本板 360×360 桌面与 BSP；桌面仅注册小智、码得与 Settings（设置）。SquareLine Demo、准星、重力球、天气、相册、画画和计算器均不在当前桌面中；部分组件源码仍保留。`made/release/` 提供烧录文件；移植范围和限制见子目录的 `PORTING.md`。
- `receiver/`：**可选的第二块 ESP32-S3 / ESP32-C3 接收端**。它建立独立热点，让码得绕开公司 Wi-Fi；接收端经 USB 将码得的配对、语音和任务请求转给电脑桥接器。`receiver/release/` 对应 S3 原生 USB，`receiver/release-esp32c3/` 对应 C3 板载 WCH 转 UART0。
- `bridge/`：**电脑桥接器**。`src/` 是可运行的客户端，包含独立语音识别入口、任务会话与内部对话记录、Codex/Cursor/Qoder 命令行适配器、WorkBuddy Open API 转交适配器、状态持久化、确认与取消接口。`public/` 是电脑工作台，入口是“大盘、助手、任务、插件”。`plugins/`、`themes/`、`examples/` 仍留在桥接器里，由桥接器加载，不拆进市场。`demo-project/` 是可以安全试用的演示 Git 仓库。
- `plugin-market/`：插件包管理。登记和分发主题、管控、agent 运行时三类包，本身不执行。
- `expert-market/`：专家包管理。登记和分发注入到 agent 的人格，本身不执行。
- `3d-model/`：码得外壳的 3D 打印模型。源文件、STL、3MF 和预览图都在这里。

## 先运行电脑端

需要 Node.js 22 或更新版本。此项目本身无需安装 npm 依赖。

```sh
cd /path/to/made
cp bridge/config.example.json bridge/config.local.json
npm start
```

大盘文案为「码得，代码触手可得」，英文为「Made,when you want to make」；任务页保持「说出任务，看见进度」，英文为「One task. An ongoing conversation.」。

浏览器打开大盘 `http://127.0.0.1:8787`；助手状态与模型在 `http://127.0.0.1:8787/assistants.html`，任务在 `http://127.0.0.1:8787/tasks.html`。先选助手和项目，再显式新建一个任务；第一句文字或语音会自动生成简短任务标题，也可在电脑任务页修改。以后选中同一任务继续说话，会沿用上下文，不会每说一句就新增任务。界面聚焦该任务的最新对话。`bridge/config.local.json` 中的 `demo` 项目可先用于验证回显与取消；真正让助手修改你的代码时，把 `projects` 中的路径改为本机 Git 仓库根目录。项目可以保留已有的未提交改动；新任务与后续对话均可继续使用这个工作目录。

### 码得的独立语音输入

码得应用的麦克风录音以 16 kHz 单声道 WAV 发给电脑。**它不依赖小智，也不需要小智 MCP 接入点。**先运行 `npm start`，再打开电脑工作台 `http://127.0.0.1:8787`。在“语音输入设置”填写**转写接口 URL、API Key、模型名**并点击“保存语音设置”；“OpenAI”和“硅基流动”按钮可快速填入各自的 URL 与模型，API Key 仍需填写自己的。默认 OpenAI URL 和模型分别是 `https://api.openai.com/v1/audio/transcriptions`、`gpt-transcribe`。设置和密钥只保存在电脑端，不写入码得。无需先在终端设置环境变量；若习惯从终端配置，也可以在启动前可选地设置：

```sh
export OPENAI_API_KEY='你的 API 密钥'
npm start
```

电脑端会向所填的 URL 发送带 `file`（WAV 音频）和 `model` 字段的 `multipart/form-data` 转写请求，使用 API Key 鉴权，并读取返回 JSON 的 `text` 字段。因此第三方服务需要兼容这套 OpenAI 音频转写协议；选中预设并不保证该服务的模型、账号和接口实际可用。云服务可能产生费用。若以后改用本机识别，可安装 [whisper.cpp](https://github.com/ggml-org/whisper.cpp) 的 `whisper-cli` 和中文模型（例如 `ggml-base.bin`，不要用 `.en` 模型），再设置：

```sh
export VIBE_ASR_MODE=whisper
export VIBE_WHISPER_MODEL='/你的模型绝对路径/ggml-base.bin'
npm start
```

没有配置语音 API Key 时，电脑面板的文字任务仍可用，码得状态文字会提示到电脑工作台配置。保存后，板端会自动刷新语音可用状态。

录音必须归入当前选中的任务；识别后只在这个任务中显示一句待确认的话，不会自动新建任务或直接运行编程助手。实体板此前经硅基流动 `FunAudioLLM/SenseVoiceSmall` 验证 BOOT 单击录音、静音自动上传、双击确认执行与三击取消。轻声检测、无大方框布局和答复滚动也已在上一版实板确认；新版任务交互仍待用户实测。OpenAI 真实转写尚未测试。

### 连接码得

电脑和码得接入同一个 Wi-Fi 时，可以继续让板子通过 UDP `8789` 自动发现电脑：启动桥接客户端，在板上打开「码得」并向上滑动解锁，扫描后先在码得列表中点选目标电脑，再核对两端显示的六位数字，并在电脑大盘确认。首次设备发现会自动开放约两分钟配对窗口；如果窗口已过期，可在大盘点“添加码得”。电脑防火墙需允许 UDP `8789` 和 TCP `8788`。

无法自动发现时，先在电脑大盘点“添加码得”开启配对窗口，再点「码得」左上角齿轮进入**接入设置**，选择**手动地址**，输入桥接机的 IPv4 或域名、端口及协议。可信局域网可用电脑的私有 IPv4 和 `8788`；跨网络使用时必须选 **HTTPS**，通常为 `443` 端口；推荐填域名，若填公网 IP，证书必须包含该 IP 的 SAN。保存后板子立即尝试连接，并沿用六位码配对：只在两端数字和目标主机一致时在电脑确认。使用公网方式时，板子仍须能接入互联网；电脑有公网地址或开启下述内网穿透，并不能替代板子的联网。地址、电脑标识和长期配对令牌保存在板上 NVS。以后每次打开或恢复「码得」并解锁后，板子都会先重新验证目标桥接机身份，再使用保存的令牌：手动地址走绑定目标接入地址的 HMAC 验证，自动发现走签名 UDP 重新发现。验证失败会重新走六位码配对。自动发现和手动地址可以在接入设置中切换，不需要重新编译固件。

电脑默认把配对令牌保存在 `state/paired-devices.json`，板子把令牌、电脑标识与地址保存在 NVS。**不需要在编译时填写电脑 IP 或设备令牌，也不需要设置 `VIBE_DEVICE_TOKEN`。**重刷时是否保留板上配对取决于是否擦除 NVS。

配对使用 `POST /pair/request` 和 `GET /pair/status`；手动地址每次连接前还会用 `GET /pair/verify` 验证保存的令牌与目标桥接机。配对后的接口包括 `GET|POST /device/sessions`、`GET /device/tasks?provider=...&sessionId=...`、`POST /device/voice?provider=...&projectId=...&sessionId=...`、`POST /device/tasks/{id}/confirm|cancel`。协议仍把内部对话记录称作 `tasks`，但产品界面的**任务就是 session**。请求携带 `Authorization: Bearer <配对令牌>`。没有选中任务时板子不会提交语音，电脑任务页发送文字也必须指定任务。码得只显示当前任务的最新交互；BOOT 双击或三击确认或取消当前待处理的话。**仅「码得」位于前台且已解锁期间**，板子每约 12 秒向电脑发送一次 `GET /device/heartbeat`；锁屏、退出应用或重启后尚未解锁时不报告，电脑按最近约 30 秒的通信判断板子离线。配对令牌仍保存在 NVS，下次进入「码得」并解锁后自动验证连接；未配对设备不会在后台主动发起配对。电脑侧编程助手的运行事件会汇总为“分析、读文件、改文件、运行命令”等阶段，在码得答复区显示；不发送命令或文件内容。WorkBuddy 只提供转交与有限的回复回读。

自动发现使用局域网 UDP；手动 HTTP 连接只适合可信局域网，可能被同网监听。**公网接入须用 HTTPS，证书必须匹配所填域名或 IP；不要直接把明文 HTTP 端口映射到公网。**配对时仍务必核对两屏数字。电脑工作台只监听本机 `127.0.0.1:8787`。

自动扫描会列出找到的电脑名称和 IP，码得上下滑动查看、点击“刷新”重新扫描；只有点选一台电脑后才验证已有配对或申请六位码。旧版桥接器没有名称时显示地址。正常再次打开「码得」并解锁后会优先验证并恢复原电脑；要更换电脑，在接入设置选择 Wi-Fi 并保存，即可重新进入选择列表。扫描、刷新和退出不会自动改配其他电脑。

### 在手机上输入连接信息

码得 → 齿轮 → 连接 → **手机配置**。手机用系统相机扫描屏幕二维码，加入 `Made-Setup-xxxx` 临时热点；通常会弹出配置网页。若没有弹出，在手机浏览器打开 `http://192.168.8.1`。也可按屏幕上的热点名称和临时密码手动连接。

网页可填写普通 Wi-Fi 名称与密码、接收端热点信息，或粘贴桥接器的完整公网 HTTPS 地址。在手机上点“保存并连接”后，码得关闭临时热点并应用设置，再按原有流程连接或核对六位配对码。Wi-Fi 不变时不用重新填写；公网连接仍需要码得使用的 Wi-Fi 能上网。

手机页由码得自身提供，无需先连上电脑，也不需要安装手机应用。入口只在手机配置页打开期间有效，10 分钟后自动关闭；返回或长按 BOOT 退出也会关闭。语音 API Key、模型与电脑任务管理继续在电脑大盘设置。

### USB 直连（只需现有码得）

用数据线把码得（当前微雪 1.85B 实现）直接插到电脑，在 **「码得」 → 齿轮 → 接入设置 → USB → 保存** 中启用。电脑仍运行桥接器；大盘的“USB 连接”显示“码得 USB 直连”。此模式不需要 Wi-Fi、接收端或内网穿透，电脑用自己的网络访问语音识别服务和 Coding Agent。

首次连接需按原有流程在电脑点“添加码得”并核对六位配对码；若码得已和这台电脑配对，则验证电脑身份后复用原配对。USB 模式独立保存身份，换电脑或桥接器重启会重新验证，未经验证不会发送旧令牌。配对、录音上传、任务列表、确认/取消和结果回显均走原生 USB Serial/JTAG；不是键盘模拟，也不会自动启动电脑程序。

只在「码得」应用位于前台、已解锁且已选择 USB 时建立协议连接；退出应用会停止设备通信，并取消仍在上传或识别中的录音，正在执行的编程任务继续由电脑管理。拔掉 USB 时显示断开，重新接上会验证后恢复；同 Wi-Fi、手动地址及可选接收端均可在接入设置切回。小智仍使用它原有的 Wi-Fi 路径。

USB 串口由桥接器使用，烧录或使用串口监视器前应先停止桥接器。固件将运行日志保留在 UART0，关闭 USB 副控制台，避免日志混入数据协议。USB 只承载应用数据；管理页面仍在电脑的 `http://127.0.0.1:8787`。

### 可选 USB 接收端

若公司 Wi-Fi 要求网页登录或设备准入，可以使用另一块 ESP32-S3 或 ESP32-C3 开发板作接收端。S3 默认使用原生 USB Serial/JTAG；当前 C3 配置使用板载 WCH USB 转串口（`1a86:55d3`）、UART0 TX21/RX20、921600 波特率，适配本次识别到的 4 MB Flash 开发板。C3 原生 USB 的配置方式见[接收端说明](receiver/README.md)。接收端建立独立的 WPA2 热点；设备只在「码得」应用位于前台且已解锁时临时连接这个热点，接收端把 HTTP 请求通过 USB 送到电脑。退出「码得」应用后，设备恢复原来的 Wi-Fi 配置，小智仍用原网络；接收端热点本身没有互联网。现有同 Wi-Fi 自动发现和公网连接继续可选。

1. 按型号选择 [S3 原生 USB 烧录说明](receiver/release/FLASH.md)或 [C3 UART 烧录说明](receiver/release-esp32c3/FLASH.md)，给**第二块板子**烧录对应三份镜像。不要混刷两个芯片的镜像，也不要刷到码得主机（微雪 1.85B）。
2. 保持电脑桥接器运行，在本机大盘的“USB 连接”查看连接状态、热点名称和密码。macOS/Linux 自动发现限定 Espressif 原生 USB `303a:1001` 和已确认的 WCH `1a86:55d3`；收到有效协议 hello 后才开始通信。若需指定接收端端口，可用 `VIBE_USB_PORT=/dev/cu.usbmodemXXXX npm start`。码得主机若也连着 USB，请先退出它的 USB 直连模式，再连接接收端。
3. 在设备上打开「码得」 → 齿轮 → 接入设置 →“接收端”，自动扫描并点选接收端热点，输入电脑大盘显示的 8 位数字密码并保存（WPA2 最少 8 位）。无需退出码得到桌面设置；也保留手动填写入口。码得连接后使用固定地址 `http://192.168.4.1:8788`；不需填写电脑 IP 或开公网穿透。
4. 若这台电脑尚未配对，在电脑大盘点“添加码得”，核对两端六位码并确认。连接同一台电脑时，两种传输方式复用经验证的配对，并同步令牌更新与撤销；不同电脑各自保存身份。下一次进入「码得」并解锁后会验证并恢复对应配对。

接收端只是 USB 和 Wi-Fi 转发器，通过原生 USB 或板载 USB 转串口向电脑提供串口。**完整功能仍需电脑上运行桥接进程**，才能读取项目、调用本机 Codex/Cursor/Qoder/WorkBuddy；管理页仍在 `http://127.0.0.1:8787`，插入接收端本身不会让电脑自动运行程序。C3 实体板已完成烧录、校验及 USB 握手；实际热点连接、配对、语音及重连仍需独立实测。

### 电脑没有公网地址时

电脑大盘的“公网接入”可选 Cloudflare Tunnel、Tailscale Funnel、ngrok 或花生壳。它们把电脑的**设备接口 `127.0.0.1:8788`** 变成公网 HTTPS 地址，供码得跨网络配对、上传语音和收取任务；电脑管理页 `127.0.0.1:8787` 仍仅在本机打开。电脑不需要公网 IP 或路由器入站端口。公网接入不会随桥接器启动自动开启，须在大盘手动选择并开启，也可手动关闭。

- **Cloudflare 临时试用地址**：电脑需按[官方安装说明](https://developers.cloudflare.com/tunnel/downloads/)安装 `cloudflared` 并能连接 Cloudflare。[Quick Tunnel](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/) 无需 Cloudflare 域名，开启后大盘显示随机 `https://…trycloudflare.com` 地址。每次重新开启，地址可能改变；Cloudflare 将它定位为测试用途，不保证持续可用。
- **Cloudflare 固定域名**：在 Cloudflare 后台创建[远程管理的 Tunnel](https://developers.cloudflare.com/tunnel/get-started/)，将托管在 Cloudflare 的公开域名作为 Published application，目标服务设为 `http://127.0.0.1:8788`，可选的 `HTTP Host Header` 覆盖项保持未设置；若改成 `localhost` 或 `127.0.0.1`，板子的地址绑定验证会失败。从后台取得该 Tunnel 的[连接 token](https://developers.cloudflare.com/tunnel/reference/tunnel-tokens/)，在电脑大盘填写 HTTPS 公网地址和 token，再手动开启。token 仅保存在电脑本机的 `state/tunnel-token`（权限 `0600`），不会下发到板子。Cloudflare 帐号和域名可能涉及费用，以其当前方案为准。
- **Tailscale Funnel 固定地址**：电脑需安装并登录支持 Funnel CLI 的 Tailscale，tailnet 启用 MagicDNS、HTTPS 证书并允许这台电脑使用 [Funnel](https://tailscale.com/docs/features/tailscale-funnel)。在大盘选择此模式并开启；首次使用可能出现浏览器授权；大盘会等待授权，最长约 2 分钟。桥接器只将 `http://127.0.0.1:8788` 通过 HTTPS `443` 发布到这台电脑的 `*.ts.net` 公网地址，码得无需安装 Tailscale。[Funnel 命令说明](https://tailscale.com/docs/reference/tailscale-cli/funnel)列出了支持的平台和端口。当前电脑尚未安装/登录 Tailscale，本项目只完成模拟测试，真实公网连接尚未验证。若桥接器异常退出后大盘提示 443 Funnel 仍指向本机 `8788`，可点“清理残留路由”；桥接器只清理这个匹配的路由，不改动其他 Serve/Funnel 配置。
- **ngrok**：按[官方安装说明](https://ngrok.com/docs/gateway/agent/getting-started/)在电脑安装 Agent，在大盘填写账号的 Authtoken；可留空地址让 ngrok 分配 HTTPS 域名，或填写账号已预留的 HTTPS 域名。点击开启后，桥接器从本机 [Agent API](https://ngrok.com/docs/gateway/agent/api) 核对实际公网地址和转发目标，确认目标精确为 `127.0.0.1:8788` 才展示给码得。Authtoken 存在电脑状态目录的私有文件中，不下发到板子。免费域名及用量受 ngrok 当前账号方案约束；临时地址变化后需要在码得更新接入地址。码得请求带有 [ngrok 指定的跳过浏览器提示请求头](https://ngrok.com/abuse)，避免提示页影响 API。
- **花生壳 HTTPS 映射**：在电脑安装并登录[花生壳客户端](https://service.oray.com/question/8321.html)，按[官方 HTTPS 映射说明](https://service.oray.com/question/8156.html)在花生壳管理平台先创建一条外网 `443` → 本机 `127.0.0.1:8788` 的映射，并取得该账号的[映射管理 API Key](https://service.oray.com/question/50663.html)。大盘填该映射的 HTTPS 域名和 API Key；点击开启或关闭时，桥接器只对这一条已经存在且目标完全匹配的映射调用花生壳启停 API，**不会创建、修改或删除映射**。开启后用随机挑战检查公网域名确实到达本桥接器、且转发保留公网 Host；核验失败不展示配对地址。API Key 仅保存在电脑状态目录的私有文件中。花生壳映射由服务商保存，桥接器异常退出后可能仍处于启用状态；再次启动桥接器会读取实际状态，可在大盘关闭。花生壳 HTTPS 域名及证书可能需要相应套餐，按服务商当前方案为准。

任一方式首次配对时，先在电脑大盘点“添加码得”，再在板上齿轮 → 接入设置 → 手动地址，填大盘显示的**域名**、端口 `443`，打开 HTTPS，点页面顶部“保存”。核对电脑与码得显示的目标主机和六位码，再在电脑确认。接入设置顶部“返回”会放弃本次编辑。公网地址对外可访问，配对仍需电脑端确认；请勿分享穿透服务密钥或设备令牌。ngrok 与花生壳目前都通过模拟接口测试，本机没有这两项服务的账号或 Agent，真实公网连接仍须在用户账号下验证。

单独使用 [DDNS](https://www.noip.com/support/knowledgebase/i-have-added-a-hostname-what-do-i-do-with-it-now) 只会把域名更新为现有公网 IP；通常还要有可到达的公网地址和端口转发。没有公网入口、处在运营商 CGNAT 下时，DDNS 无法代替内网穿透。

所有公网方式都要求**板子有可用网络并能访问对应公网地址**。如果公司网络禁止板子联网，开启隧道也无法让它连接；可尝试让板子使用有互联网的手机热点。公网 HTTPS 会校验证书链、目标主机和有效期。进入「码得」后板子在前台同步网络时间；尚未取得可信时间时不会发送公网配对、任务或语音请求，15 秒后会显示失败，可单击 BOOT 重试。若所在网络阻止时间同步，请让板子改用可联网的 Wi-Fi。


### 码得上的操作

- 打开独立的「码得」应用后，先从锁屏向上滑动解锁，再点左上角齿轮，在设置首页进入“接入设置”。编辑页顶部左边是“返回”，右边是“保存”；选局域网自动发现或手动输入桥接地址后须点“保存”才会应用。连接后，一屏只显示一个助手和对应的大动物头像。先点右上角 `+` 新建该助手的任务；点旁边的 `-` 并二次确认，可删除当前任务及对话记录；首次说话后自动从指令生成简短标题，也可在电脑任务页改名。**左右滑只切换助手**；在上方任务标题区上下滑或轻点标题切换这个助手的任务。屏幕只显示当前任务的最新交互；中部文字区上下滚动，待确认时显示完整指令，执行后显示进度和答复。除设置齿轮与新建任务的 `+` 外，屏幕不提供触摸确认或取消按钮。
- 选中任务后，单击板上 **BOOT** 开始录音。说话结束后约 1.2 秒静音会自动上传；开始后 8 秒内没有检测到语音会报错且不上传，最长录制 30 秒。识别出的指令先回显，双击 BOOT 才会执行这句话，三击 BOOT 可取消；录音中三击也会取消本次语音。若指令超过板端接收长度，码得会阻止确认并提示在电脑任务页核对全文。答复在板端最多传输 1200 UTF-8 字节，超长时保留开头和末尾，中间以省略号标记，并提示到电脑任务页看全文。当前工具不可用时，以电脑工作台中的状态和提示为准。
- 按住 BOOT 约 1.2 秒即返回 Brookesia 桌面，无需等松开；退出时会取消进行中的录音。小智是独立应用，在小智界面单击 BOOT 键开始聆听；这些按键操作只作用于当前打开的应用。
- 板子没有单独的 RESET 键；需要重启时，可长按 **PWR**，或拔下并重新插入 USB 供电线。

## 编程工具

电脑工作台“助手”页的“编程助手模型”可分别设置 **Codex、Cursor、Qoder** 的模型，保存后从下一次指令生效。Codex 默认 `gpt-6-astra`；Cursor 和 Qoder 留空时使用各自 CLI 的默认模型。这里设置的是**编程模型**，与“大盘”中的**转写模型**分开。WorkBuddy 本地助理接口不提供模型字段，需要在 WorkBuddy 桌面应用中选择，电脑桥接器无法为它指定模型。

- **Codex**：本机安装并登录 `codex` 后可用。桥接器在指定 Git 仓库中运行受工作区沙箱限制的非交互任务。默认模型 `gpt-6-astra` 已在这台电脑上通过 CLI 冒烟测试；若你的账号不能使用，在电脑工作台改为可用模型。首次尚未保存网页模型设置时，也可在启动前设置 `VIBE_CODEX_MODEL`。模型可用性仍以实际账号和客户端为准。
- **Cursor**：本机安装并登录 `cursor-agent` 后可用。无界面运行会对已加入允许列表、且经码得或电脑确认的 Git 目录传入 `--trust`；同时开启 Cursor 沙箱和自动审核。只将你信任的代码目录加入配置。
- **Qoder**：安装并登录官方 `qoder` CLI 后可用；当前电脑尚未安装，所以面板会显示不可用。
- **WorkBuddy**：腾讯桌面应用通过 [WorkBuddy 开放平台本地助理 API](https://open.workbuddy.cn/docs/openapi) 转交消息。该接口没有选择本地助理会话的字段，因此桥接器中的 WorkBuddy 任务只是**本地整理记录**，不能保证不同任务上下文隔离，码得新建时也会提示。该 API 也未提供可靠的目标代码目录和已发送任务撤回能力，因此默认关闭。取得 `WORKBUDDY_ACCESS_TOKEN` 和相应 OAuth 权限后，还需在 `config.local.json` 中显式将 `workbuddy.allowUnscopedDispatch` 设为 `true`。若令牌同时具有 `user.localassistant.readable` 权限，桥接客户端会按消息 ID 增量读取回复，并在电脑面板和码得当前答复中回显。消息历史没有可靠关联桥接任务的字段；出现后续用户消息时，桥接客户端停止归属后面的回复。转交成功或收到回复都不表示编程完成。

### 任务上下文与电脑接手

一个任务固定一个助手和一个 Git 项目。你可以在这个任务里连续说话或提交文字；每句话先等待确认，确认后助手再继续。Codex、Cursor、Qoder 会使用该任务保存的原生 CLI 会话 ID 续接，因而共享对话上下文。若一次执行没有取得可续接的原生 ID，桥接器会报错并拒绝假装续接。切换助手要选择该助手自己的任务；点 `+` 新建任务才开启独立上下文。旧版历史记录会迁入旧任务，不能凭空恢复过去没有保存的助手上下文。

任务在电脑上的同一 Git 项目目录运行，你可以随时用编辑器打开该目录，检查改动并手动修改代码。执行中请先等待完成或在工作台取消，避免同时改动同一文件。同一任务的后续对话可沿用仓库已有改动，也允许你在两轮之间手动修改文件。

- **Codex**：桥接器与 Codex 桌面使用同一台电脑、同一会话数据目录时，首次执行取得可续接的原生会话 ID 后，工作台显示“在 Codex 打开”，通过 `codex://threads/<会话 ID>` 打开。若浏览器无法打开应用链接，可复制 `codex resume --include-non-interactive <会话 ID>` 命令在终端接手。后续对话用同一个 ID 继续；任务不一定自动出现在 Codex 默认列表中。旧版使用 `--ephemeral` 创建的记录没有可恢复会话，无法补出这个入口。
- **Cursor**：首次执行取得原生会话 ID 后，后续对话用 `cursor-agent --resume <会话 ID>` 继续。任务页可复制此命令在终端接手；也可复制项目路径，在 Cursor 打开同一目录查看和修改代码。[Cursor 官方确认](https://forum.cursor.com/t/local-ide-agent-chats-and-the-agent-cli-still-use-separate-session-stores/165486)，本地 CLI 会话与桌面聊天使用不同存储，目前不会同步到 Cursor 的聊天列表，无法在桌面聊天里续聊。
- **Qoder**：桥接器记录首次执行返回的原生会话 ID，后续对话通过官方 CLI 的 `--session-id` 续接。当前电脑尚未安装 Qoder，续接需在装好并登录后实测。参见 [Qoder CLI 参数说明](https://docs.qoder.com/cli/cli-reference)。

所有助手的每次指令都要先经本机或码得确认。这里管理的是**由本桥接客户端创建的任务**，不会自动读取各桌面助手过去的全部会话。码得只可选择电脑预先允许的 Git 项目，不能指定任意本机路径或程序。正在运行的本地 CLI 执行可取消；WorkBuddy 消息一旦转交，后续权限请求和取消仍需在 WorkBuddy 内处理。

## 当前硬件实现：1.85B 固件与出厂功能

[微雪出厂说明](https://docs.waveshare.com/ESP32-S3-Touch-LCD-1.85B/Instructions-For-Use)列出原厂 Brookesia 桌面里的小智、天气、音乐、相册、视频等应用，但其[公开仓库](https://github.com/waveshareteam/ESP32-S3-Touch-LCD-1.85B)目前只提供完整出厂 `.bin` 和简化示例，未见整套出厂 App 的源码。本项目以官方 Brookesia 示例作底座，参考微雪 [1.75 圆屏开源应用](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.75/tree/main/firmware/brookesia)移植小智等功能，并按当前使用场景精简桌面。当前桌面只保留小智、码得和 Settings；其他演示及工具应用均不注册到桌面。当前工程不能视为原厂固件原样保留。

小智与码得是桌面里的两个独立应用，录音时通过音频会话锁互斥使用麦克风。上一版应用镜像已在实体 1.85B 上刷入并通过 esptool 哈希校验，用户确认过配对、录音、双击执行、三击取消、长按退出、轻声输入及答复滚动。当前支持完整动态助手目录和图标，并保留 USB 直连与可选接收端模式的应用镜像已用 ESP-IDF 5.5.5 构建，为 5,803,328 字节，factory 分区余量 1,086,144 字节；**当前中文桌面名版本已刷入现有 1.85B，并通过 esptool 写入哈希校验；此前版本的 USB 直连已在实板恢复原配对并收到心跳，实际语音上传曾生成待确认交互；本轮为中英文界面与设备独立语言选择更新，未重新提交语音任务；独立接收端已取得 C3 板子，仍待完整链路联调**。`release/` 中的预构建镜像无需写入电脑地址或令牌；在「码得」接入设置中选择 Wi-Fi、手动地址、接收端或 USB 即可。已在本机备份刷写前的应用分区，建议保留原厂整片 Flash 备份，以便恢复原来的桌面与设置。

刷写前应按 [Espressif 文档](https://docs.espressif.com/projects/esptool/en/latest/esp32s3/esptool/basic-commands.html)备份整片 Flash；微雪提供[出厂恢复镜像与步骤](https://docs.waveshare.com/ESP32-S3-Touch-LCD-1.85B/Firmware-Flashing)。码得和接收端各有独立的 ESP-IDF 5.5 固件工程；后续构建和移植细节分别见 `made/` 与 `receiver/`。

本版也修复了旧任务显示后界面停止响应的问题：LVGL 改为同步绘图，恢复空白区域滑动，并关闭「码得」的系统边缘导航手势。实板已确认左右切助手、齿轮及长按 BOOT 退出恢复；退出后 USB 回到待机，心跳停止。

接入设置先显示两行两列的大按钮，四种连接方式之间留出 18 像素空隙；选中后进入对应配置页，可点“更换方式”回到选择页，点顶部“保存”才应用连接方式。
