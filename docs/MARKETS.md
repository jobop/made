# 市场能力划分

三种市场各管一层，并且只做包管理。一个能力只进一个市场，不把人格、技能和码得控制写进同一个包。

市场与码得固件、接收器、桥接器运行时解耦。市场不执行包，不连接板子，也不保存配对令牌或 hook 密钥。包下载并安装到固定的用户目录 `~/made/{plugins,themes}`（可用 `MADE_HOME` 覆盖）之后才生效，桥接器启动时自己扫这个目录。桥接器里随代码发布的内置包在 `bridge/builtin/`，`examples/` 和 `src/agents/` 是开发位置，都不搬进市场目录。同名时用户目录覆盖内置。

| 市场 | 管什么 | 生效位置 |
| --- | --- | --- |
| 插件市场 | 码得本身的能力 | 安装到桥接器后由桥接器执行；需要上板的资源、事件注册和命令再下发到码得 |
| 技能 | agent 的可复用能力 | 不在本仓库自建广场，沿用现成技能广场；挂到 agent 后，下次任务注入该助手的技能目录 |
| 专家市场 | 注入到 agent 的人格 | 安装到桥接器并挂到一个 agent 后，该助手每次执行都带上 |

技能和专家不经过码得的事件与命令。插件市场里的东西也不写入人格正文或技能正文。

## 插件市场

插件市场控制码得本身。其中的插件分三种。

### 主题插件

改码得的外观：颜色、锁屏图、提示音，以及同一套主题声明里的其他外观资源。

主题插件不下发人格，不注册事件，不增加 agent 运行时。

### 管控插件

接收码得事件。事件只有被已激活的管控插件登记之后，板侧才上报。

收到事件后可以：

- 自行处理，或交给某个 agent 处理
- 输出结果
- 把码得控制命令放进该设备的命令队列
- 调用外部 hook

事件上报和命令下发是两条独立的设备接口。插件可以在处理事件时入队，也可以在处理函数返回之后用 `send` 入队。桥接器也可以不经过事件，按板侧清单直接入队。命令可以是文字提示、附带语音、或板侧已有操作（切换主题、音量、助手、任务、录音、确认、取消）。码得另行领取队列；带语音的命令再把语音本体取走。未确认的命令会保留到下次领取。

插件入队的命令必须来自板侧已经公开的命令清单，并且由这个插件声明。桥接器直接入队只受板侧清单约束。外部 hook 的地址和密钥留在桥接器，不下发到码得。未登记的事件保持板上的原有行为，不上报。

管控插件的事件注册、事件上报、命令领取和命令确认属于设备侧接口，四种接入方式都要能走到同一套设备 API。

### agent 扩展

扩展 agent 运行时：接上一种助手的执行方式，包括会话、模型、进度和取消。

agent 扩展不改码得主题，不订阅码得事件。人格放进专家市场，可复用的方法沿用现成技能广场，不写进运行时插件。

## 技能

技能是 agent 的能力扩展。本仓库不自建技能广场，沿用现成的技能广场。

一份技能是一套可复用的方法、步骤和材料，供 agent 在相关任务里使用。同一个技能可以挂到多个 agent，更新一处即可。技能要安装到桥接器并挂上才生效，不自动作用于所有助手。

技能不改码得外观，不订阅码得事件，也不代替人格。只属于某一个助手的长期职责，写在专家里，不写进技能。

## 专家市场

专家市场管理注入到 agent 的人格包。包安装到桥接器并挂到一个 agent 之后，才在每次执行时注入。

人格说明这个助手是谁、负责什么、边界在哪里、怎样交付。它属于一个 agent，每次执行都注入。给用户看的介绍文字只用于展示，不进入执行提示。

人格不包含可复用技能的正文，也不下发到码得。

## 归类

| 要加的东西 | 归入 |
| --- | --- |
| 锁屏颜色、图、提示音 | 插件市场 · 主题插件 |
| 摇一摇、按键、倾斜等事件之后的处理、命令或外部 hook | 插件市场 · 管控插件 |
| 一种新的 agent 运行时 | 插件市场 · agent 扩展 |
| 多个助手都能用的步骤、清单、材料 | 现成技能广场，安装到桥接器后挂到 agent |
| 某个助手固定的职责、边界、说话方式 | 专家市场 |
