# 国际化 / Localization

当前支持 `zh-CN`（简体中文）与 `en`（English）。中文产品名为“码得”，英文为小写 `made`。

## 语言设置

电脑桥接器与码得各自提供语言选择。电脑语言同时作为码得「跟随电脑」模式的语言来源。在网页顶部选择语言，通过需要本机操作令牌的 `POST /api/settings/language` 保存 `{ "locale": "en" }` 或 `{ "locale": "zh-CN" }`。非法语言标识不会保存。

`GET /api/state` 返回当前 `locale`，三个管理页面据此同步。语言设置单独保存，不重写语音密钥、助手模型、配对凭据或任务内容。现有安装默认简体中文。

认证后的 `GET /device/config` 同样携带 `locale`。码得仅在「跟随电脑」模式使用有效语言值更新自身界面；「中文」或「English」手动选择有更高优先级，连接后不会被覆盖。模式与有效语言保存到独立的 NVS 设置中，没有收到有效值时沿用之前的设置。原有 Wi-Fi、公网、USB 直连和接收端均传递同一份配置。接收端只是转发器，无须解析语言字段。

配置通常在重连时立即获取，保持连接时约每 31 秒刷新。语言切换不是强制重启、重新配对或重建会话。

码得设置首页只显示「连接」「语音」菜单入口；进入「连接」才选择连接类型，进入「语音」才选择「中文 / English / 跟随电脑」，子页返回均回设置首页。语言无需连接桥接器即可选择，连接后也可独立选择。Brookesia 桌面与最近应用的图标名称固定使用中文「码得」，应用内部文字随当前语言切换，避免切换语言时重新注册桌面应用。

设备请求可附带 `uiLocale=zh-CN|en`，使服务器返回的内置状态、错误和默认任务占位与设备自己的语言一致。该参数不修改电脑保存的语言；`/device/config` 顶层 `locale` 始终表示电脑偏好。USB 与接收端按原协议透明转发路径。

## 翻译边界

翻译应用自己的导航、按钮、说明、错误提示、运行状态、日期显示及辅助功能标签。用户输入、第一句生成的任务标题、手动重命名、助手原始回复、项目标签、命令、路径、模型 ID、设备自定义名称和插件自定义内容均保留原文。

未输入第一句话的任务可显示本地化的“新任务 / New task”占位；一旦用户提供内容，不再根据文字匹配翻译标题。

网页使用明确的文字键和静态翻译标记，禁止对整页文字或整个 API JSON 做搜索替换。动态值通过占位参数插入，作为文本渲染，不作为 HTML 执行。后端只在属于桥接器自己的已知消息字段上翻译；未知第三方错误原样保留，便于排查。

语音请求仅发送兼容转写接口需要的音频与模型信息，不根据界面语言强制中文或英文。应用界面语言不等于语音识别支持的语言列表，也不会自动要求助手翻译已有对话。

## 代码入口

- `public/i18n.js`：网页语言状态、取词与静态节点更新。
- `public/i18n-static.js`：静态页面中英文文字。
- `public/i18n-messages.js`：动态界面中英文文字。
- `src/language-settings.mjs`：`language-settings.json` 的校验和原子保存。
- `src/i18n.mjs`：桥接器自身的消息字典，由 `server.mjs` 在明确的响应字段上使用。
- 板端 `firmware-brookesia/components/vibe_i18n/`：轻量双语词典、语言校验与持久化。界面线程刷新文字，网络线程不直接操作控件。

增加一条应用文案时，先在所属词典添加中英文，再从页面或代码引用；不要在业务逻辑中各自复制翻译。短小的设备按钮需单独写适合小屏的译文，不直接复用网页长句。

增加新语言时需同时补齐三端的字典、支持值校验、语言选择器和测试。当前板端字体与布局主要针对中文和拉丁文字；新增其他书写系统需要检查字体覆盖、输入方式和布局，并更新固件。当前支持语言之间切换不需刷机。助手插件名单与图标仍由桥接器下发，不因本地化而改回固件内置。

## 验证要求

运行 `npm test` 验证设置持久化、鉴权、非法值处理、设备配置传播，以及原任务/语音/配对接口。网页需检查三页的语言切换、刷新后的保持、未提交表单内容保留、长英文和窄屏布局。板端需检查有效/无效 locale、NVS 恢复、中文与英文标签、录音和确认取消状态、接入页与配对页的实际 LVGL 布局。

小智、原厂系统应用及任意第三方助手的原始输出不属于这套界面字典。其语言由各自应用或服务控制。
