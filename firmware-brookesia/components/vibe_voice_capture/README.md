# Coding Agent 独立录音

`vibe_voice_capture` 是 Coding Agent 应用的录音层，不调用小智 App 或小智 MCP。它与小智并列使用 `board_voice_audio` 板级硬件层；音频会话锁保证两个应用不会同时占用 ES7210/ES8311 与 I2S。

在码得应用前台，先点码得右上角 `+` 显式新建任务并选中；这里一个任务就是一个会话，可以连续对话。无任务时单击 BOOT 不会录音。选中任务后单击 BOOT 开始录音。设备先检测到连续语音，再等待约 1.2 秒静音，自动结束并上传；启动后 8 秒都未听到语音会提示重试且不上传，最长录制 30 秒。再次单击不会提前上传，三击 BOOT 可取消录音，长按约 1.2 秒则取消并退出应用。从 ES7210 TDM 槽 0（MIC1）和槽 2（MIC2）中选取有声通道，采集 16 kHz、16 bit PCM，封装成单声道 WAV，经带令牌的局域网 HTTP `POST /device/voice?provider=...&projectId=...&sessionId=...` 发到电脑桥接端。录音启动时必须传入合法任务会话 ID；桥接端调用独立语音识别器，并将转写结果作为该任务的当前待确认指令，不会自动新建任务。第一句指令会自动生成简短任务标题，可在电脑任务页改名。码得只显示该任务的最新交互。录音不存入 Flash。

公开 API 在 `include/vibe_voice_capture.hpp`：`start(bridge_url, token, provider, project_id, session_id)`、`cancel()`、`status()`；任务会话 ID 为 UUID，缺失或格式不合法时拒绝录音上传。静音检测器在 `include/voice_activity_detector.hpp`，不依赖云端，也不作语音转文字；它只决定何时结束一段话。ESP32 PSRAM 最多暂存约 1 MB 音频。`status()` 返回 Idle、Recording、Uploading、Submitted 或 Error 和屏幕可显示的状态文案。
离开应用或取消时，正在录制的音频会丢弃。上传中三击 BOOT 会先记下取消意图；当前 HTTP 请求返回后，若电脑端已接受上传并返回内部指令编号，设备会向电脑端发送取消请求。取消完成前屏幕显示正在取消当前指令。如果上传响应丢失或取消请求失败，设备会提示到电脑任务页检查并手动取消当前指令。无论哪种情况，当前指令在明确确认前都不会运行编程助手。

`test_voice_activity_detector.cpp` 可在电脑上验证轻声说话、说话后静音、未开口超时、短噪声、连续讲话和 30 秒上限。1.85B 实板测得安静时最大块电平约 11、正常说话时约 137–166；旧版固定 220 门槛会漏掉说话。检测器以第一块声音估计底噪，再使用较低的相对门槛（实测安静环境约 22），要求连续约 125 毫秒说话才算开始；如果第一块就是轻声说话，还会利用持续超过 125 毫秒的音量变化识别它。说话后的短尖峰或不足 80 毫秒的噪声不会反复重置 1.2 秒停顿计时。仅在已检测到语音、准备上传前，对 PCM 做最多 12 倍的有界软件增益，让电脑端识别较小音量。`test_pcm_upload_gain.cpp` 验证增益边界与 16 位饱和裁剪。不同房间的表现仍以实板试说为准。
