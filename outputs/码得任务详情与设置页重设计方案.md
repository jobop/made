# 码得板子侧 UI 重设计方案：任务详情页 + 设置页

> 屏幕双变体：1.85B **360×360 圆屏** / 2.8" **240×320 方形竖屏**（当前 `sdkconfig` 为 `CONFIG_BSP_BOARD_LCD_2_8=y`，即实际构建目标是方形屏）
> 设计基准画布：360×360（`made_layout.hpp` 的 `made_rect()` 在运行时按真实屏自动区分，两块屏共用同一套坐标源码）
> 因此本方案的坐标均以 360 画布书写，方形屏的专属差异见 §3.3 与 §4.4
> 涉及文件：`made/components/vibe_theme/vibe_theme.cpp`、`made/components/brookesia_app_vibe/esp_brookesia_app_vibe.cpp`

## 1. 设计目标

现状两个页面的共性问题：

| 页面 | 问题 |
| --- | --- |
| 任务详情（抽屉） | 状态是纯文本混在标题行，无进度可视化，正文无容器，视觉动线缺失 |
| 设置 | 6 个等宽通栏按钮纵排，无分组、无图标、当前值不外露，可扫读性差 |

重设计原则：**不引入新字体、不改字库、不改 360 画布换算**，全部在现有 token 体系内做"层级化"——用容器、色彩、间距建立层级，而不是用新资源。

## 2. 设计 token

### 2.1 色彩表（写入 `vibe_theme.cpp` Palette，RGB565 友好）

| Token | 色值 | 用途 | 对 bg_page 对比度 |
| --- | --- | --- | --- |
| `bg_page` | `0x0B1830` | 页面底色（沿用） | — |
| `bg_panel` | `0x10243B` | 卡片 / 列表行底色（沿用 bg_row 提升为主容器色） | — |
| `bg_row` | `0x16273E` | 二级行 / 徽章底 / 进度条轨道 | — |
| `bg_chip_accent` | `0x123B31` | 状态徽章底（accent 的深色衍生） | — |
| `accent` | `0x1C856F` | 主按钮填充 / 进度条 | — |
| `text_accent` | `0x8CE4CB` | accent 文字 / 图标 / 百分比 | 8.9:1 ✓ |
| `text_primary` | `0xF1F5FF` | 标题、行名称 | 15.8:1 ✓ |
| `text_secondary` | `0xB8C9E4` | 正文、说明 | 10.2:1 ✓ |
| `text_hint` | `0x8A97B8` | 辅助时间戳、section 标签、当前值 | 6.1:1 ✓ |
| `success` | `0x4CD964` | 状态点·运行中/已完成 | 仅作点缀 |
| `warning` | `0xF5A623` | 状态点·待确认/排队 | 仅作点缀 |
| `danger` | `0xE5484D` | 状态点·失败 / 删除确认 | 仅作点缀 |
| `danger_soft` | `0x3B1E28` | 删除按钮的弱化底色（新增） | — |

规则：状态永远「点 + 文字」双通道传达（色盲可用，符合 WCAG 1.4.1）；`text_hint` 从 `0x9FADD0` 微调至 `0x8A97B8`，拉开与 secondary 的层级差。

### 2.2 字体刻度（受字库约束的现实方案）

中文点阵字库 `font_puhui_16_4` 只有 16px 一档，**不做插值缩放**（点阵笔画会糊）。层级改用「字号不变、色彩与容器区分」：

| 层级 | 字体 | 颜色 | 用途 |
| --- | --- | --- | --- |
| Display 数字 | `montserrat_26` | `text_primary` | 任务分页 "1/3"、音量值、进度百分比 |
| 标题 | `font_puhui_16_4` + 500 权重感 | `text_primary` | 任务标题、页面标题 |
| 正文 | `font_puhui_16_4` | `text_secondary` | 结果内容、说明 |
| 辅助 | `montserrat_12`（拉丁）/ puhui16 + hint 色 | `text_hint` | 时间戳、section 标签、当前值 |

## 3. 任务详情页（抽屉）

### 3.1 布局规格（自上而下，360 画布坐标）

| 区域 | 规格 | 说明 |
| --- | --- | --- |
| 分页器 chip | 左上，高 26，radius 13，底 `bg_row`，内容 "任务 1 / 3"（数字用 montserrat_16） | 替代现在标题行里的 "任务 1/3 ·" |
| 状态徽章 | 右上，高 26，radius 13，底按状态：运行中 `bg_chip_accent`/`text_accent`、成功 `success` 15% 底、失败 `danger_soft`/`danger` 文字 | 4px 状态点 + 状态词，取代 `statusName()` 拼文本 |
| 任务标题 | y≈150，单行 LONG_DOT，`text_primary` | 从标题行剥离分页与状态后可独占一行，更长可截断 |
| 活动/进度区 | 标题下 4px：running 态显示**不确定式活动条**（轨道 `bg_row` 高 5，`accent` 高亮段循环扫动，只表达"进行中"），活动条下方用 `text_secondary` 排 `task.progress` 原文（桥接器下发的自由文本，非百分比）；非 running 态两者都不显示 | **数据事实**：`job.progress` 是 agent 输出流抓的自由文本（jobs.mjs，≤80 字符），链路无百分比/步骤信号，故**禁止确定性百分比条**——那是在显示编造的数据 |
| 结果卡片 | 宽 230（圆屏安全），radius 16，底 `bg_panel`，内边距 12，放进现有 `answer_area_` 滚动区 | 正文 `text_secondary`，底部时间戳 `text_hint`；附件（图片/二维码）渲染在此卡片内 |
| 底部按钮行 | 三个 46×46 圆钮（位置不变）：**+ 用 `accent` 实底白字（主操作），− 用 `danger_soft` 底 `text_secondary` 字（弱化破坏性），齿轮沿用 `bg_row`** | 现状三钮同权重，主次不分 |

### 3.2 状态徽章映射

| 状态 | 徽章底 | 文字 | 状态点 |
| --- | --- | --- | --- |
| 待确认 | `bg_row` | `text_secondary` | `warning` |
| 已排队 | `bg_row` | `text_secondary` | `text_hint` |
| 运行中 | `bg_chip_accent` | `text_accent` | `success`（呼吸：opa 255↔120，600ms） |
| 已完成 | `bg_chip_accent` | `text_accent` | `success`（静态） |
| 失败 | `danger_soft` | `danger` 提亮版 `0xF2888C` | `danger` |

### 3.3 方形屏 240×320 差异（当前构建目标）

方形屏没有圆弦裁切，**全宽 240px 上下通吃**——这是它相对圆屏的结构性优势，布局应利用而非照搬 360 换算的保守边距：

| 区域 | 240×320 规格 | 与圆屏差异 |
| --- | --- | --- |
| 顶部提示条 | 常驻显示「下拉收起 · 左右滑切任务」 | 圆屏顶部会被弦切，方形屏可常驻，不必挤进标题区 |
| 分页器 + 状态徽章 | 同一行：chip 左对齐 x=12，徽章右对齐 x=228，高 26 | 两者间距更充裕，徽章文字可完整显示 |
| 进度条 | 轨道全宽 216（x 12→228） | 圆屏只有 180 |
| 结果卡片 | 宽 228，可显示 3–4 行正文（约多 1 行） | 圆屏宽 230 但上下收窄，可用纵向空间少 |
| 底部按钮行 | 三钮居中，y=316，46px 圆钮 | 相同；方形屏下方无裁切，可再下移 4px |
| 布局换算 | 现有 `made_page_*` 按比例铺满高 320，无需新代码路径 | 沿用 `made_rect()` 分支 |

### 3.4 微交互

| 交互 | 参数 |
| --- | --- |
| 状态切换 | 徽章 opa 淡入 200ms ease_out（只动 opacity，GPU 友好） |
| 进度条 | ~~`lv_bar` LV_ANIM_ON 300ms~~ → 活动条循环扫动动画（lv_anim 0→100 循环，仅 drawer 可见时运行，离开抽屉即删动画） |
| 结果卡片入场 | 随抽屉现有滑入动效，不额外加动画 |
| 徽章呼吸点 | 仅 running 态，opa 动画，与精灵 10Hz 节流互不干扰（独立 lv_timer） |

禁止事项：不做整屏 transform_scale 动画（真机已证实全屏逐帧失效会卡）；不加阴影到卡片上（RGB565 下阴影抖动明显，沿用按钮投影范式即可，卡片免阴影）。

### 4.2 行组件规格

| 属性 | 值 |
| --- | --- |
| 行高 | 44px（触控目标 ≥44，符合 WCAG 2.5.8） |
| 行底色 | `bg_panel`，radius 11，行间距 6 |
| 图标位 | 22×22 容器 radius 6 底 `bg_chip_accent`，内嵌 LVGL 内置符号（`LV_SYMBOL_WIFI` 等，montserrat 14），色 `text_accent` |
| 名称 | puhui16，`text_primary`，距图标 10 |
| 当前值 | 右对齐，`text_hint`；**连接成功类状态用 `text_accent`**（如"已连接"） |
| 箭头 | `LV_SYMBOL_RIGHT`（montserrat_12），`text_hint` |
| section 标签 | 高 20，`text_hint`，全大写不适用中文 → 直接「连接 / 偏好 / 系统」 |
| 按下态 | 整行提亮 7%（复用 `styleSurface` 的按下范式） |

### 4.3 二级面板调整

| 面板 | 改动 |
| --- | --- |
| 音量 | ±按钮 → `lv_slider`（轨道 `bg_row` 高 6，滑块 20×20 圆，填充 `accent`），大数字 montserrat_26 显示当前值 |
| 电源 | 数值切换按钮 → 分段控件（segmented）：每段高 40，选中段 `accent` 底白字 |
| 语言/主题 | 行样式与主列表统一（现有滚动列表保留，只换行皮肤） |
| 返回 | 顶部导航化：左上 ‹ 箭头（44×44 命中区）替代底部「返回」按钮，释放底部空间 |

### 4.4 方形屏 240×320 适配（当前构建目标，非缩略版）

方形屏是当前 `sdkconfig` 的实际构建目标，以下为完整规格而非圆屏的降级：

**设置主列表**
- 行宽 216（x 12→228），行高 44、图标 22×22、radius 11 全部与圆屏一致——组件规格完全复用，仅容器宽度变化
- 无圆弦裁切 → 一屏可见「连接」整组（3 行）+「偏好」标签 + 2 行，滚动量比圆屏少约 1 行
- 顶部导航（‹ + 标题）有完整矩形空间，标题可精确居中于 240px

**任务详情抽屉**
- 结果卡片宽 228，正文可见 3–4 行（圆屏约 2–3 行）
- 进度条可做全宽 216，百分比数字放在条右不与轨道争空间
- 顶部手势提示条可常驻（圆屏因弦切只能挤进内容区）

**实现注意**
- 现有代码已有 `made_rect()` 分支（如 `esp_brookesia_app_vibe.cpp` L856 处理窄屏行距、L4025 处理 provider 标签），新控件一律走 `made_page_y/made_s` 换算，不写死 240/320
- 矩形屏行距警告：L856 注释表明 360 坐标在 240 宽下两行文字间距不足一个字形高——新增行组件必须用 `made_fit()` 检查间距，不要直接搬 360 画布的行距
- 验证时两块屏都要出图：`npm run sim` 后分别确认 240×320 与 360×360 无遮挡、无截断

## 5. 无障碍核对清单（WCAG 2.2 AA）

- [x] 正文对比度 ≥4.5:1：三档文字色对 `bg_page`/`bg_panel` 全部通过（见 2.1 表）
- [x] 状态不只靠颜色：点 + 文字双通道（1.4.1）
- [x] 触控目标 ≥44px：行高 44、圆钮 46、返回 44（2.5.8）
- [x] 按下态提亮 + 下沉双反馈，不只靠颜色（2.4.7 焦点可见的触屏等价物）
- [x] 动效克制：仅 opacity + bar 填充，无位移动画堆叠（2.3.3 前庭安全）
- [ ] 失败态文字 `0xF2888C` 需真机 RGB565 量化后复查对比度（预计 ≈5:1，达标但需截图确认）
