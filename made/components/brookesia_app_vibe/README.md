# 独立码得 桌面应用（ESP-Brookesia）

微雪 ESP32-S3-Touch-LCD-1.85B 的 Brookesia 桌面可单独打开 **码得**，不调用小智语音或小智 MCP。**一个任务就是一个持续对话的会话**：右上角 `+` 显式新建任务，第一句指令自动生成简短标题，也可在电脑任务页改名；后续说话继续同一个任务。当前有任务时，点 `-` 并核对标题，可删除当前任务及其对话记录；执行中的任务若无法停止，桥接器会拒绝删除。每个编程助手单独占一页：名单、名称、能力和实际图标像素均由已配对桥接器下发，固件没有默认助手或动物绘图模板。首次连接、重连验证和重新进入应用时，仅显示连接状态；收到有效空名单时显示“暂无助手”。左右滑只切换助手；在上方“任务 n/N · 标题”区域上下滑或轻点标题切换该助手的任务。屏幕仅显示当前任务的最新交互；中部文字区上下滑只滚动当前指令、进度或答复。桥接若标记 `instructionTruncated`，板端会阻止双击 BOOT 确认，并提示到电脑任务页核对全文；`resultTruncated` 则在答复末尾提示到电脑任务页看全文。板子负责录音、显示和批准当前指令；电脑桥接负责转写、项目白名单和工具执行。

**录音与任务**：无任务时单击 BOOT 不会录音，屏幕提示点 `+`。选中任务后单击 BOOT 开始录音，检测到讲话结束后的约 1.2 秒静音便自动上传到当前任务，最长录制 30 秒；8 秒内未检测到语音则报错且不上传。电脑端尚未配置语音识别时，屏幕提示到电脑工作台设置转写接口 URL、API Key 和模型名。转写后只显示当前待确认指令，不新建任务；双击 BOOT 才执行，三击 BOOT 取消。录音或上传时三击会取消本次语音；上传成功但回显尚未出现时，三击仍能取消刚提交的指令，双击须等回显后才可确认。切换助手、任务或退出应用会取消正在录制的语音。若网络在提交后中断，当前指令仍可能等待确认；未确认前不会运行编程助手。小智与 Vibe 只共用底层音频硬件及互斥锁，小智的语音逻辑不参与 Coding Agent。

**BOOT 键**：仅在码得 应用处于前台时生效。选中任务后单击开始录音；当前待确认指令双击确认、三击取消或否认。录音或上传过程中三击取消本次语音。长按约 1.2 秒立即返回 Brookesia 桌面，退出时取消录音。最后一次松开后等待 420 毫秒才判定单击、双击或三击，因此开始录音会有短暂延迟；下一次按键正在按下时，不会提前执行前一个手势。切换助手、任务或离开应用会清除未完成手势。小智仍只在自己的应用内处理 BOOT 单击聆听。

## 注册与配置

### 可选 USB 接收端

在 码得 的“设置 → 接入设置”选择“接收端”，从电脑管理页抄写接收端提供的热点名称（SSID）和密码。板子只在 码得 前台连接这个专用热点，直接访问接收端的 `http://192.168.4.1:8788`，不需要接入场所 Wi-Fi，也不会运行局域网 UDP 自动发现。首次使用仍需在电脑页面核对六位配对码并确认；接收端配对令牌单独保存，不覆盖原有电脑桥接配对。离开 码得 后会恢复原有 Wi-Fi；无接收端时继续选“同 Wi-Fi”或“公网”。接收端仍需电脑侧执行程序来运行 coding agent。

### 原有电脑桥接

在 `main/CMakeLists.txt` 的 `REQUIRES` 中加入 `brookesia_app_vibe`，在 `main/main.cpp` 引入 `esp_brookesia_app_vibe.hpp`，并于 `phone->begin()` 后安装：

```cpp
phone->installApp(esp_brookesia::apps::VibeCoding::requestInstance());
```

BOOT 键无需在 `main` 另行绑定。进入 码得 后，板子在同一局域网用 UDP 广播寻找电脑工作台（端口 8789）；首次配对时，板子和电脑都显示同一个六位数字。确认数字一致后，只在电脑端点“确认配对”。电脑发给板子的长期令牌和电脑标识写入板子的 NVS；之后进入应用会自动连接，电脑 IP 变化时会按电脑标识重新发现。整个过程不用在编译时填写电脑地址或设备令牌。Wi-Fi 可在 Brookesia Settings 内设置；电脑防火墙需允许发现端口 8789 和设备端口 8788。若曾解除配对或更换电脑，先在电脑工作台点“添加设备”，再进入板上应用。

电脑端工作台的“语音输入设置”提供转写接口 URL、API Key、模型名三字段，以及 OpenAI 和硅基流动预设；预设只填 URL 与模型，密钥需用户自行填写。API 密钥只保存在电脑端，不写入板子；终端环境变量 `OPENAI_API_KEY` 仍可作为可选配置。电脑向所填 URL 发送带 `file`（WAV）和 `model` 字段的 `multipart/form-data` 请求，读取响应 JSON 的 `text` 字段，因此服务需兼容 OpenAI 音频转写协议。未设置密钥时仍可在电脑上输入文字，板端状态文字会提示电脑端配置。也可将电脑端 `VIBE_ASR_MODE` 设为 `whisper`，并用 `VIBE_WHISPER_MODEL` 指定本地 whisper.cpp 模型。识别完成后只在已选任务中显示当前待确认指令，仍需双击 BOOT 或在电脑工作台确认才执行。硅基流动 `FunAudioLLM/SenseVoiceSmall` 已通过上一版实体板的语音上传、云端转写和待确认请求验证；OpenAI 真实转写及新版任务交互尚未实板验证。

电脑端“编程助手模型”与语音转写模型是分开的设置：Codex、Cursor、Qoder 可分别指定 CLI 运行模型，保存后从下一次指令生效；WorkBuddy 本地助理接口不接受模型参数，需要在 WorkBuddy 桌面应用中选择。模型 ID 不写入板端。

配对协议：UDP 发现请求 `VIBE_DISCOVER_V1`，电脑回复 `VIBE_BRIDGE_V1 <port> <bridgeId>`；板子发送六位数字和随机 nonce 至 `POST /pair/request`，电脑确认后板子轮询 `GET /pair/status` 领取一次长期令牌。任务协议：`GET /device/config`；`GET /device/sessions?provider=<id>`；用户点 `+` 新建任务时才发 `POST /device/sessions?provider=<id>&projectId=<id>`；`POST /device/sessions/{id}/delete`；`GET /device/tasks?provider=<id>&sessionId=<uuid>`；`POST /device/tasks/{id}/confirm|cancel`。语音组件用 `POST /device/voice?provider=<id>&projectId=<id>&sessionId=<uuid>` 上传 16 kHz/16 bit/单声道 WAV。仅在 码得 前台打开期间，每约 12 秒 `GET /device/heartbeat`；退出或重启后停留桌面不报告，电脑以最近约 30 秒的通信判断离线。配对令牌仍保存在 NVS，下次进入自动连接；未配对时不主动发起后台配对。已配对的任务请求使用 `Authorization: Bearer <token>`。项目默认值来自电脑桥接配置。Codex、Cursor、Qoder 的 CLI 事件流只回传“分析、读文件、改文件、运行命令、整理答复”等通用阶段，不传命令或文件内容；WorkBuddy 仅转交和有限回读，电脑本地助理接口无法保证不同任务的原生会话隔离，板端新建时会提示用户核对。

当前局域网协议使用明文 HTTP。六位码用于让用户识别两端屏幕，不能抵御控制同一局域网的攻击者监听或篡改通信；仅在可信家庭或办公网络使用。固件 NVS 默认不加密，拥有板子物理访问权的人可能提取令牌。

中文界面和任务回显使用项目已依赖的 `xiaozhi-fonts` 16px 普惠字库，字形放在固件 Flash，不占用约 2.5 MB 连续 PSRAM；常见汉字覆盖比 LVGL 内置 16px 字库完整。极生僻字仍可能没有字形。本目录的 `test_boot_click_gesture.cpp` 可在电脑上编译运行，以验证多击状态机。用户已在上一版实体板上确认单击录音并回显待确认请求、双击执行、三击取消、长按退出、轻声输入和答复滚动；新版 `+` 新建任务、标题自动生成、任务切换与持续对话虽已烧录但仍待用户实测。

## 下发助手图标

`GET /device/config` 的每个 `providers[]` 包含 `icon`：`format: "indexed4"`、`width`/`height`（1～48）、`palette`（1～16 个无 `#` 的 `RRGGBBAA`）、`data`（标准 Base64；每字节高 4 位为第一个像素，无行补齐，奇数像素最后低 4 位必须为 0）。可选 `background`/`accent` 为 `#RRGGBB`。严禁用图像 URL 代替像素；格式不合法只显示中性占位，不丢弃该助手。

最多 12 个助手，每个图标最多缓存 1152 字节索引像素；仅当前选中图标在 LVGL 线程展开为最多 9216 字节 BGRA，并显示为最大 64 像素。相同助手 ID 更换图标会使 LVGL 图像缓存失效并重画。网络线程只更新模型；不操作 LVGL，也不改同步绘图配置。
