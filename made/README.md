# ESP32-S3-Touch-LCD-1.85B Brookesia 固件基底

设备产品名为 **码得（made）**，不限定屏幕形状。本目录是当前微雪 ESP32-S3-Touch-LCD-1.85B（360×360 圆形屏幕）的硬件适配。

此目录基于微雪官方 `05_esp-brookesia` 示例，目标板是 **ESP32-S3-Touch-LCD-1.85B**。它包含本板的 ST77916 屏幕、CST816S 触摸、音频、SD 卡 BSP，以及 360×360 的 ESP-Brookesia Phone 桌面样式。当前桌面只注册 **小智、码得、Settings（设置）**；SquareLine Demo、准星、重力球、天气、相册、画画、计算器均不在桌面中。小智参考微雪官方 1.75 英寸圆屏 Brookesia 源码并适配本板 BSP；设置和码得为本项目编写。仓库中仍留有部分早期移植组件作为历史源码，但不代表当前桌面已安装。这仍不是 1.85B 原厂固件的逐字复刻，完整适配状态见 [PORTING.md](PORTING.md)。

## 开机与锁屏

开机自动打开码得锁屏；应用每次打开或恢复时也先锁定。绿色小豆跳舞，中英文文案交替为「码得，代码触手可得」与「Made,when you want to make」。向上滑动解锁后才启用桥接连接与心跳，进入原有助手、任务和设置界面；锁屏时单击、双击、三击 BOOT 不执行任何录音或任务操作。长按 BOOT 约 1.2 秒从锁屏或应用内返回桌面。系统 Wi-Fi 可继续使用已保存的凭据，但不代表码得已连接电脑桥接器。

本轮三应用桌面、开机自动打开与锁屏操作仍待实板验收；下文既有实板记录属于此前版本。

## 构建

使用 ESP-IDF 5.5.3 或兼容的 5.5 版本：

```sh
idf.py build
```

当前支持完整动态助手目录和图标，并保留 USB 直连与可选接收端模式的应用镜像已用 ESP-IDF 5.5.5 构建，`release/01_factory.bin` 为 5,810,288 字节；**当前版本已刷入现有 1.85B，并通过 esptool 写入哈希校验；新接收端交互仍待第二块板子实测**。本版齿轮设置首页提供「连接」「语音」，进入「语音」再选择「中文 / English / 跟随电脑」，在线离线均可选择，手动偏好独立保存；桌面应用名固定为「码得」。当前会话可通过右上角 `-` 核对标题并确认删除；桥接器会同步清理该会话及其对话记录。Wi-Fi 密码以及码得接收端 SSID、密码、手动地址和端口均改用每行最多五键的大键盘；码得输入框会打开独立编辑页，点「完成」后返回接入设置，再点「保存」使连接配置生效。此前版本的顶部“返回”及语音交互已由用户确认。首次构建会从 ESP-IDF Component Registry 下载依赖。正式烧录前请备份设备现有固件和配置，并查看 [PORTING.md](PORTING.md) 中仍待验收的交互清单。

从本目录执行 `idf.py -p PORT flash` 会按构建生成的烧录清单写入 bootloader、分区表、factory 应用、`assets` 字体资源和 ESP-SR `model` 语音模型。**首次安装**若只烧录应用 `.bin`，会缺少字体与离线唤醒资源；已完整刷入同版分区布局和资源的板子可只更新应用。factory 分区为 6,889,472 字节，新版镜像剩余 1,086,144 字节；应用超过 4 MiB 的 `ota_0` 分区。

`vibe_wifi` 会在启动时尝试使用已有的 Wi-Fi NVS 凭据；也可在本地 `menuconfig` 中设定 SSID 和密码作为后备。设置应用提供板上扫描网络、选择网络和触摸输入密码。是否能读取原厂留下的凭据取决于原厂的存储方式及刷写时是否保留 NVS。进入码得并上滑解锁后，同一 Wi-Fi 下通过 UDP `8789` 扫描电脑；码得先显示电脑名称与地址列表，点选后才申请配对码，再核对两屏六位数字并在电脑确认。已有配对时会先验证原电脑并自动恢复；要换电脑，重新选择 Wi-Fi 接入并保存。手动配对前先在电脑大盘点“添加码得”打开配对窗口；再在码得点左上角齿轮 →“接入设置”，选手动地址，输入桥接机 IPv4 或域名、端口和 HTTP/HTTPS。编辑页顶部左侧“返回”放弃编辑，右侧“保存”应用设置：可信局域网通常用私有 IPv4、HTTP、`8788`；跨网络用 HTTPS、通常 `443`；推荐域名，公网 IP 须有匹配 IP SAN 的证书。保存后立即连接并走相同的六位码确认，板上配对页显示目标主机。电脑将令牌保存在本机状态目录，板子存入 NVS；无需在编译时填入电脑地址或令牌。

接入设置也提供“接收端”模式：另一块通用 ESP32-S3 接收端建立 WPA2 热点，通过原生 USB 接电脑。码得填入电脑大盘显示的热点名称和密码后，在码得前台解锁后临时加入该热点，固定连接 `http://192.168.4.1:8788` 并沿用六位码配对；退出码得后恢复之前的 Wi-Fi。接收端热点凭据使用独立 NVS 键，不覆盖原 Wi-Fi 配置。连接同一台电脑时复用经验证的配对，并同步令牌更新与撤销；不同电脑的身份各自保存。接收端热点没有互联网；小智仍需要原有联网 Wi-Fi。详情见[接收端说明](../receiver/README.md)。

每次打开或恢复码得并解锁后，板子在使用旧令牌前先验证桥接身份：手动地址使用绑定目标接入地址与桥接 Host 的 HMAC 挑战，自动发现使用签名 UDP 应答；只对通过验证的同一桥接机续连，失败则重新配对。添加第二块板子时从电脑工作台点“添加码得”。仅码得前台已解锁期间，板子每约 12 秒发送一次心跳；锁屏、退出或重启后尚未解锁时不再报告，电脑根据最近约 30 秒通信判断离线。配对令牌仍保存在 NVS，下次进入并解锁后自动验证连接；未配对时后台不会主动发起新配对。局域网发现与手动 HTTP 通信是明文，只应在可信网络使用；公网须用 HTTPS，不应直接映射明文 `8788` 端口。固件使用 CA bundle 校验证书链、主机名和有效期；码得前台同步网络时间，时间未就绪时不会发起公网 HTTPS 请求，15 秒后显示失败，可单击 BOOT 重试。局域网自动发现时防火墙需允许 UDP `8789` 和 TCP `8788`。

跨网络时电脑可在大盘手动开启 [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/get-started/)、[Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel/)、[ngrok](https://ngrok.com/docs/gateway/agent/getting-started/) 或[花生壳 HTTPS 映射](https://service.oray.com/question/8156.html)。Cloudflare 临时试用地址是随机 HTTPS URL；固定域名需远程管理 Tunnel、连接 token 和指向 `http://127.0.0.1:8788` 的 Published application 路由。Tailscale 需电脑安装并登录支持 Funnel CLI 的客户端，tailnet 启用 MagicDNS、HTTPS 证书和 Funnel 权限；开启后使用电脑的 `*.ts.net` 公网 HTTPS 地址。ngrok 需在电脑安装 Agent 并保存 Authtoken；板端所有桥接 HTTP 请求带 `ngrok-skip-browser-warning: 1`，兼容免费地址的提示页。花生壳需在电脑安装并登录客户端，先配置外网 HTTPS/443 到本机 `8788` 的映射，再在桥接器填写域名和 API Key；桥接器只管理完全匹配的现有映射。这些方式都只发布设备接口 `8788`，电脑管理页 `127.0.0.1:8787` 不经隧道；板子仍须能联网。ngrok、花生壳和 Tailscale 未在此电脑使用真实账号联调。

此前实板已验证 Wi-Fi、配对、单击录音及静音自动上传、双击确认、三击取消、长按退出、轻声输入与答复区滚动；新版手动地址与公网路径仍需实板验收。

早期相册移植代码按原厂 `/sdcard/photo` 与移植工程 `/sdcard/photos` 两个目录查找基线 JPEG，但相册**目前不在桌面中**；这些目录说明仅供未来恢复相册时参考。原厂音乐、视频和录音应用尚未移植。
小智语音应用已加入源码并使用 1.85B 双麦/扬声器适配层；首次使用需完成小智平台激活。小智与码得是两个独立桌面应用，只共享板级音频驱动。码得使用紧凑的无卡片码得布局：左上齿轮进入接入设置，一个任务就是一个会话，右上 `+` 显式新建任务；首次说话后从指令自动生成简短标题，可在电脑任务页改名；左右滑只切换助手，上方“任务 n/N · 标题”区域上下滑或轻点切换任务。屏幕只显示当前任务的最新交互，中部文字区上下滚动阅读待确认指令和执行答复。每次语音都提交到已选任务，不会自动开新任务。超长指令会阻止板端确认，提示到电脑核对全文；答复传输最多 1200 UTF-8 字节，超出时保留开头与末尾并提示到电脑查看完整内容。单击 BOOT 开始录音，语音结束后静音约 1.2 秒自动上传，双击确认、三击取消、按住约 1.2 秒退出；屏幕不提供触摸确认或取消按钮。运行中回显通用阶段提示，Codex、Cursor 和 Qoder 分别来自其 CLI 事件流，不显示命令或文件内容；WorkBuddy 只能转交和有限回读，其本地接口无法选择目标会话，因此不能保证不同任务的上下文隔离。此前已在实板确认录音、执行、取消、退出、轻声检测及答复滚动；新版接入设置、任务交互、小智升级后状态、双麦反复切换仍待确认。OpenAI 真实云端转写也未测试。

编程模型在电脑工作台的“编程助手模型”中按 Codex、Cursor、Qoder 分别设置；Cursor 和 Qoder 留空时使用各自 CLI 默认模型。语音转写模型在另一处“语音输入设置”中设置。WorkBuddy 本地助理 API 不提供模型参数，需要在 WorkBuddy 桌面应用中选择。

官方示例随附的 `dependencies.lock` 含原作者机器上的绝对本地路径，不能在其他电脑直接重用。此目录不带该锁文件；首次构建将重新解析依赖。

本版也修复了旧任务显示后界面停止响应的问题：LVGL 改为同步绘图，恢复空白区域滑动，并关闭码得的系统边缘导航手势。实板已确认左右切助手、齿轮及长按 BOOT 退出恢复；退出后 USB 回到待机，心跳停止。

接入设置先显示两行两列的大按钮，四种连接方式之间留出 18 像素空隙；选中后进入对应配置页，可点“更换方式”回到选择页，点顶部“保存”才应用连接方式。

## 码得 USB 直连

码得 → 齿轮 → 接入设置新增“USB”，保存后通过原生 USB 数据线连接电脑桥接器，无需另一块板子或 Wi-Fi。`vibe_usb` 组件复用有界 NDJSON 数据协议；配对层用独立 USB 凭据槽，先验证连接身份再发送任务令牌。每次打开/恢复码得并解锁后重新验证，电脑进程重启或 USB 重连时同样重验。退出会停止握手、心跳和未完成转写；双击确认、三击取消与任务上下文保持原有交互。

实板已恢复原配对并收到心跳；一次实际录音经 USB 上传后，在电脑生成新的语音交互并进入执行。第二块接收端的无线路径仍待对应硬件验证。

USB 数据通道不兼任日志控制台：`CONFIG_ESP_CONSOLE_SECONDARY_NONE=y`，运行日志从 UART0 输出。不要重新打开 USB secondary console；烧录前停止占用串口的桥接器。
