# 1.85B Brookesia 移植与精简桌面清单

## 当前证据

微雪 [1.85B 官方仓库](https://github.com/waveshareteam/ESP32-S3-Touch-LCD-1.85B/tree/main/Firmware)的 `Firmware/` 只有 `ESP32-S3-Touch-LCD-1.85B-Factory.bin`，没有对应的完整原厂应用源码。本目录来自同仓的 [05_esp-brookesia 示例](https://github.com/waveshareteam/ESP32-S3-Touch-LCD-1.85B/tree/main/Examples/ESP-IDF-V5.5.3/05_esp-brookesia)：桌面框架、360×360 样式和本板 BSP 已就位；其原始 `main/main.cpp` 只安装 SquareLine Demo。本项目曾扩展成十应用候选；当前已按使用场景精简桌面。

微雪[原厂固件说明](https://docs.waveshare.com/ESP32-S3-Touch-LCD-1.85B/Instructions-For-Use)列出的应用包括设置、小智、天气、音乐、SquareLine、相册、视频、录音、Chipmunk2D。早期移植计划希望尽量复现这套体验；当前用户选择只保留小智、码得与 Settings 三个应用的桌面。

可复用的完整应用源码来自微雪官方 [ESP32-S3-Touch-AMOLED-1.75 `firmware/brookesia`](https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.75/tree/main/firmware/brookesia)，固定来源提交 `e4344e70c2fa78a13e8a06566507f1ba8af6672a`。它有 13 个圆屏应用：SquareLine、Calculator、DrawPanel、SpecAnalyzer、MusicPlayer、Gallery、VideoPlayer、Recorder、Settings、AIChats（小智）、Gravitysphere、Crosshair、Button Test。其中 **没有天气和 Chipmunk2D**，这两项需单独实现或取得 1.85B 原厂源码。微雪 1.8 AMOLED 的 `firmware/brookesia` 也是完整开源工程并含小智，但其 368×448 矩形屏不如 1.75 圆屏布局接近本板。

两个仓库根目录均为 Apache-2.0；1.75 源码中 `XiaozhiApp/third_party/xiaozhi_esp32/LICENSE` 为 MIT。移入的每个组件及依赖仍需保留原许可证和声明。原厂 BIN 是恢复镜像，不能视为可修改源码。

## 硬件与工程差异

- **桌面核心**：两边的 `brookesia_core` 都标注 `0.6.0-beta2`，顶层 `esp_brookesia.hpp` 完全相同；但 CMake、依赖清单及部分实现不同。以本目录内经过 1.85B 适配的核心为准，逐个加入应用。
- **显示与触摸**：1.85B 为 360×360 ST77916 LCD + CST816S；1.75 为 466×466 CO5300 AMOLED + CST9217。保留本目录的 1.85B BSP、屏幕驱动、触摸方向与 360×360 样式。移植应用中的固定坐标、字体、图标与圆屏安全区都要重新检查。1.75 `main.cpp` 中 CO5300 的偶数像素对齐刷新逻辑不得直接搬来。
- **电源与电池**：1.85B 使用 BQ27220 电量计；1.75 使用 AXP2101。1.75 的 `system_status`、`Settings` 和 Button Test 含 AXP2101/TCA9554 专用逻辑，需要改为 BQ27220、本板 BOOT/PWR 行为。微雪说明 1.85B 的 PWR 键不能作为自定义功能键。
- **音频**：两板同为 ES7210 双麦与 ES8311 输出，但引脚、功放和 BSP 初始化路径不同。本项目新增 `board_voice_audio`，在小智与 Vibe 语音间协调板级录放音会话。一次实际圆屏录音已上传并经硅基流动转写生成待确认指令；双麦细节、扬声器和两个应用反复切换仍需分别确认。原厂录音、频谱与音乐应用尚未接入此会话层。
- **存储**：1.85B 是 4-bit SDMMC，1.75 工程按 1-bit SDMMC 配置；`storage_service` 依赖 1.75 BSP，未来恢复相册时需使用 1.85B 的挂载与卸载接口。原厂 1.85B 文档的相册目录为 `photo`，1.75 Gallery 用 `photos`；早期移植代码兼容两个目录，但 Gallery 当前未注册到桌面。
- **分区与资源**：1.75 完整工程用 16 MB Flash 中 8 MB 应用、6 MB SPIFFS、960 KB 语音模型分区；本目录保留了 1.85B 示例的 factory、OTA 与 assets 布局，并在 Flash 尾部追加 960 KB `model` 分区。小智运行前必须完整刷入 ESP-SR 模型；新版应用镜像为 5,803,328 字节，factory 分区为 6,889,472 字节，余量 1,086,144 字节；它超过 4 MiB OTA 槽。上一版应用镜像已在实体板刷入并校验，长期运行内存余量仍需观察。
- **依赖**：1.75 应用工程依赖 `esp_lvgl_adapter`、`esp-sr`、`esp_xiaozhi`、`xiaozhi-fonts`、音频编解码及播放器等组件。1.85B 示例已随仓提供板级 BSP 和 Brookesia Core，但并未包含上述完整应用栈。移植时固定 ESP-IDF 5.5 系列和每个依赖版本，避免被最新组件自动升级破坏兼容性。

7. 用户已在上一版实板验证单击录音与静音自动上传、双击确认、三击取消、长按 BOOT 立即返回桌面；电脑端约 30 秒后显示离线，符合仅 Vibe 前台上报心跳的设计。无方框圆屏布局和答复区上滑显示后半段也已获用户确认。此前的显式新建任务、自动标题、助手横切、任务切换和任务内持续对话已经刷入，但接入设置顶部“返回”已由用户在实板确认可用；“保存”、手动 HTTPS 与 Cloudflare/Tailscale 公网连接尚未实板验收；其他重点包括多应用反复切换、断电恢复及长期内存余量。OpenAI 真实云端转写尚未测试。

## 当前状态

本目录是官方 1.85B Brookesia 示例扩展的**单一整合固件工程**，当前桌面只注册小智、码得（made）、Settings 三个应用，并有 `vibe_wifi` 自动连接服务。SquareLine Demo、Crosshair、Gravitysphere、Calculator、DrawPanel、Gallery 和 Weather 相关源码仍保留，但当前不在桌面；原厂音乐、视频、录音和 Chipmunk2D 尚未在本目录复现。桌面设置页提供 Wi-Fi 配网、亮度和电池状态；码得内齿轮管理本应用的桥接接入方式与独立界面语言。电脑端可选 [Cloudflare Tunnel](https://developers.cloudflare.com/tunnel/get-started/)、[Tailscale Funnel](https://tailscale.com/docs/features/tailscale-funnel/)、[ngrok](https://ngrok.com/docs/gateway/agent/getting-started/) 或[花生壳](https://service.oray.com/question/8156.html)发布 `127.0.0.1:8788` 设备接口的公网 HTTPS 地址；Cloudflare 临时地址每次可能改变，固定地址需远程管理 Tunnel token 与 Published application 路由。Tailscale 需电脑安装并登录支持 Funnel CLI 的客户端，tailnet 允许 Funnel、MagicDNS 和 HTTPS 证书，公网地址为 `*.ts.net`。电脑管理页仍为本机 `127.0.0.1:8787`，公网接入只在用户手动开启时运行；Tailscale、ngrok 与花生壳在本机没有完成真实公网连接测试。公网接入方式仍要求板子连接 Wi-Fi 和互联网；内网穿透不会解决板子未能联网的问题。USB 直连则不依赖板子 Wi-Fi。开机自动打开码得锁屏；每次打开或恢复也先锁定。仅码得前台已解锁期间按约 12 秒间隔上报心跳，锁屏和退出后停止；配对令牌仍保存，电脑按最近约 30 秒通信判断离线。上一版应用镜像已在实体 1.85B 上单独刷入并通过 esptool 哈希校验；重启日志确认 Brookesia、触摸芯片和 Wi-Fi 正常启动。用户已完成配对，并确认轻声语音指令可完成、无方框布局和答复区滚动可用。小智此前据用户反馈已恢复，本轮升级后仍待确认。本轮镜像为 5,803,328 字节，factory 分区余量 1,086,144 字节，4 MiB OTA 槽仍不足；顶部“返回/保存”触摸位置已修复并单独刷入应用，顶部“返回”已在实板确认可用；“保存”和新增接入操作仍待实板验收。电脑侧服务和协议在项目其他目录开发，与本固件基底解耦。

官方示例附带的 `dependencies.lock` 记录了原作者机器上的绝对本地路径，本目录移除了这个不能复用的锁文件，首次构建需要联网重新解析依赖。

本轮补齐 ngrok 的 `ngrok-skip-browser-warning: 1` 请求头，覆盖配对、心跳、任务、取消及语音上传四个 HTTP 客户端入口；仍校验公网 HTTPS 证书。花生壳模式要求电脑端已存在外网 HTTPS/443 到本机 `127.0.0.1:8788` 的映射，桥接器只用官方 API 核对和启停该映射，并在显示公网地址前通过随机挑战验证转发确实回到本桥接器。当时的应用镜像 SHA256 为 `a0fb0186c3f058ab7c1d03ed636575f424eef99f4ad045bbf24d7fbec8eff387`，已单独烧录到实板的 factory 应用分区并通过 esptool 哈希校验；没有擦除 NVS。ngrok 和花生壳的真实公网链路仍需账号条件下实测。


## 2026-09-30：单圆屏 USB 直连

接入设置新增“USB”，使用板子原生 USB Serial/JTAG 传输配对、语音、任务与心跳，不依赖 Wi-Fi；电脑仍需运行桥接进程。仅 Vibe 前台且选中 USB 时启用，退出发出 bye 并取消在途请求。身份授权同时绑定当前连接标识和已验证令牌，换电脑后重新验证或核对六位码；网络与 USB 的配对凭据独立保存。保留原 Wi-Fi、公网和第二块接收端路径。USB 应用日志已从该数据口移到 UART0，以免干扰协议。

USB 直连阶段的固件已通过 ESP-IDF 5.5.5 编译、刷入连接的 1.85B 并通过 esptool 哈希校验。当时只更新 factory 应用，没有擦除 NVS；烧录前应用备份位于工作区 `work/board-app-before-usb-direct.bin`。以下为该阶段实板验收记录；最新镜像与本轮验证见文末动态插件目录一节。电脑端已实际识别该圆屏的 direct USB 通道（设备编号 288485b3e6e0），原配对恢复且设备在线；未产生额外配对请求，27 个任务及 29 条历史交互保留。直连模式实际录音已在电脑生成新的 device_voice 交互，随后进入执行；本版已由用户确认滑动、齿轮及长按退出恢复。电脑侧 63 项测试全部通过；USB C++ 协议测试及 7 个配对身份验证场景通过。

### 历史任务页面卡住的修复

实板诊断发现，卡住时 USB 心跳与 BOOT 检测仍在运行，Vibe 刷新回调已返回，但 LVGL 显示事件停在 `FLUSH_FINISH`，后续刷新计数不再增加；长按退出已被检测到，却无法由界面线程执行。故障位于界面绘制路径，尚未定位到上游同步原语的具体缺陷。

本版设置 `CONFIG_LV_OS_NONE=y`、`CONFIG_LV_DRAW_SW_DRAW_UNIT_CNT=1`，让 LVGL 在调用线程同步绘图。它不关闭 ESP-IDF 的 FreeRTOS；显示适配器仍使用 FreeRTOS 任务和递归互斥锁保护所有界面访问。同时恢复 Vibe 根页面的触摸命中，并关闭该应用的系统边缘导航手势，避免空白处滑动丢失或触摸被系统遮罩截获。

修正版已刷入实板，用户确认旧任务出现后可左右切换助手、打开齿轮、长按 BOOT 返回桌面；诊断显示界面刷新持续运行，退出后 USB 状态回到 waiting、active=false。保留可选诊断：以 `VIBE_UI_DIAGNOSTICS=1` 启动电脑桥接器，会在已认证心跳中记录界面/按键刷新间隔和显示阶段计数，不记录任务文字或令牌；默认关闭日志。此轮验证覆盖故障复现步骤，长期运行和其他应用仍需持续观察。


### 接入方式防误触调整

接入方式由一排四个 67×32 小按钮改为两行两列 126×64 大按钮，横纵间隔均为 18 像素，置于圆屏内部安全区域。选择方式和编辑参数分开显示；选择页隐藏键盘和保存，详情页通过“更换方式”返回选择，仍须显式保存才改变连接。回到手动地址前先恢复输入长度，避免接收端 SSID 长度限制截断地址；进入详情时重置键盘目标和模式。

键盘显式使用 TOP_LEFT 对齐后再设置坐标，修正 LVGL 默认底部对齐导致手动地址/接收端键盘落在屏外的问题。使用真实 LVGL 和项目字体渲染选择页、USB、手动地址及接收端详情页，检查按钮间距、圆屏边界、字段与键盘无重叠。

输入框主体与占位提示明确使用 Puhui 中文字体，修正原 Montserrat 仅西文字体导致 IP、端口、SSID 和密码提示出现缺字方框。空白输入框、中文 SSID 和密码圆点均已用真实 LVGL 字库渲染检查。


### 多桥接器选择列表

首次连接或在接入设置显式保存 Wi-Fi 模式时，圆屏显示电脑名称和 IP 列表（最多 12 台），可上下滚动并手动刷新。V3 广播带电脑名称，兼容旧 V1 地址回应；同一身份或端点去重，扫描不生成配对请求。用户点选后才验证所选电脑或申请六位码；已有配对的正常重开仍通过签名发现恢复原电脑，恢复失败回到选择列表，不自动选择其他电脑。选择和刷新从 UI 入队，由 worker 执行；退出、重新扫描、换接入方式会使旧选择失效。连接失败仍显示所选 IP，重试不会改选其他电脑。

已通过电脑侧 64 项测试（无跳过），配对组件 USB 回归 7 场景和列表选择 8 场景。真实 LVGL 渲染与触摸模拟覆盖长名称省略、三行可见/上下滚动、慢速横向划动不误选、正常点按、扫描禁用和无网络提示。整机固件通过 ESP-IDF 5.5.5 编译。多台真实电脑同时扫描与实体触摸仍需在对应网络现场验收。接收端本身不提供大盘网页，也不会自动打开电脑浏览器，电脑仍需运行桥接程序。
